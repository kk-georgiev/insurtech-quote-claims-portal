## Findings

Sources: an inline architecture/layering check (this session), one aggregate-views sub-agent (pattern divergence, duplication, spec reconciliation), and three `bmad-review` lenses (adversarial, edge-case-hunter, verification-gap) run over the full epic diff. 24 raw findings, consolidated to 16 below (some triangulated by 2-3 independent sources).

### Checked and clean

- **AD-2 layering** — grepped every `import com.motorinsurance.*` in `backend/src/main/java`: no module imports another module's `domain`/`persistence` package. The one cross-module import anywhere is `quote.application.QuoteService` → `pricing.application.{PricingResult,PricingService}` — exactly the sanctioned "sole entry point" pattern. No violations found.
- **Entity/JPA conventions** — `auth.domain.User`, `quote.domain.Quote`, and all five `pricing.domain` entities consistently expose no setters, use a `protected` no-arg constructor, and follow the same `@Column` style. The one structural difference (pricing's `@GeneratedValue(IDENTITY)` reference-data entities vs. `User`/`Quote`'s app-assigned `UUID.randomUUID()`) is justified by the different entity kind (seeded reference data vs. runtime-created rows), not an inconsistency.
- **Exception-to-HTTP mapping idiom** — every `ApiException` subclass across all three modules follows the same shape and namespacing; the "lookup → `orElseThrow(new SpecificException(...))`" pattern is applied consistently everywhere it recurs.
- **God-class / size growth** — ranked the epic's file churn; no file is oversized in absolute terms (largest production class is `Quote.java` at 175 lines, largest test class `QuoteControllerTest.java` at 327 lines for 16 HTTP scenarios across 2 endpoints — both proportionate to what they do).
- **Spec-to-implementation reconciliation** — every Story 1.1-1.6 acceptance criterion was checked against actual code (not just tests) and is satisfied, with one partial exception (below).

### Findings requiring a decision or follow-up

1. **Auth module (Stories 1.2/1.3) has essentially no dedicated automated test coverage — the epic's single most significant gap.** Triangulated independently by three separate analyses:
   - No `RegistrationServiceTest`, `AuthenticationServiceTest`, or `AuthControllerTest` exists anywhere (`backend/src/test/java/com/motorinsurance/auth/` contains only `application/JwtServiceTest.java` and `config/JwtAuthenticationFilterTest.java`).
   - Duplicate-email registration (409 `AUTH_EMAIL_TAKEN`) — Story 1.2's most distinctive AC — has **zero** test coverage; grepping the whole test tree for `AUTH_EMAIL_TAKEN`/`EmailAlreadyRegistered` returns no matches outside production code.
   - The unknown-email login path (the no-user-enumeration defense `AuthenticationService`'s own javadoc and `DUMMY_PASSWORD_HASH` mechanism exist to protect) is never exercised by any test.
   - Every downstream test (`QuoteControllerTest`, `JwtAuthenticationFilterTest`) mints its bearer token via `jwtService.issueToken(...)` directly — no test decodes a token that actually came out of a real `/api/v1/auth/login` call, so the auth↔quote boundary's most basic contract ("login hands back a token carrying this user's real id and role") has never been verified end to end.
   - *Disposition:* fix now (proposed action item, highest priority). *Upstream lesson:* Stories 1.5/1.6 both got dedicated `bmad-code-review` passes during this session; Stories 1.2/1.3 (implemented earlier, before this session) did not get the same treatment applied to their test suites specifically. Recommend running a `bmad-code-review` pass on the auth module's own diff before Epic 2 builds more identity/role logic on top of it.

2. **`AUTH_EMAIL_TAKEN` doesn't attach a field-level error, unlike the pricing exceptions established one story later.** `EmailAlreadyRegisteredException` uses the 3-arg `ApiException` constructor (no `FieldError`), while `UnknownRegionCodeException`/`UnsupportedInstallmentCountException` (Story 1.5) both attach one for the field the error is actually about. `InvalidCredentialsException`'s omission is justified (no-enumeration); this one isn't. *Disposition:* fix now (small, mechanical). *Lesson:* none beyond "the convention hadn't been established yet when 1.2 was written" — not recurring once 1.5 set the pattern.

3. **Email normalization (`trim().toLowerCase()`) is duplicated verbatim in `RegistrationService` and `AuthenticationService`**, with a comment in each acknowledging the two must stay in sync — but no shared helper extracted. Locale-dependent (`toLowerCase()` with no `Locale.ROOT`) as a secondary point from the same code. *Disposition:* fix now (extract a small `Emails.normalize(String)` using `Locale.ROOT`, call it from both places).

4. **Story 1.2's NFR-4 ("field-level validation enforced identically at API and DB layer") is not fully satisfiable as written.** The password-length rule (`@Size(min=8,max=100)`) has no DB-layer equivalent because only the bcrypt hash is stored, never the raw password — there is no column to constrain. The email-format rule (`@Email`) is API-only too; `V2__create_users_table.sql` only enforces `NOT NULL UNIQUE` and a length cap. *Disposition:* spec reconciliation, not a code defect — propose narrowing NFR-4's wording (e.g., to structural/length rules that *can* be mirrored) rather than leaving a literally-unmeetable NFR on the books.

5. **`QuoteService.calculate`'s `quoteRepository.save(quote)` has no `DataIntegrityViolationException` handling for the `customer_id` foreign key**, unlike `RegistrationService.register`, which explicitly catches the analogous violation. Not reachable today (no account-deletion feature exists), but two independent lenses (adversarial, edge-case-hunter) converged on it specifically because `auth.domain.Role`'s javadoc already names AGENT/LIQUIDATOR/ADMINISTRATOR "for Epic 2" — the day account lifecycle management exists, a live token for a since-removed user turns into an opaque 500 instead of a clean 401/404. *Disposition:* defer, but flag for Epic 2 specifically (not indefinitely) — this is exactly the kind of cross-epic interaction a single-story review can't see coming.

6. **No token revocation/logout mechanism; a role change or account deactivation wouldn't take effect for up to the JWT's 8-hour lifetime.** Not a defect against Milestone 1's own declared scope (Story 1.4's spec explicitly lists "no refresh token, login rate limiting, or lockout" as non-goals), but role staleness specifically becomes a real concern once Epic 2 introduces role-based routing for staff accounts whose roles may need to change. *Disposition:* defer to Epic 2 planning, record as a design question rather than a Milestone-1 defect.

7. **`POST /api/v1/quotes` returns the default `200 OK` instead of `201 Created`**, inconsistent with `POST /api/v1/auth/register`'s `@ResponseStatus(HttpStatus.CREATED)` for the same "this created a new resource" case — the only two resource-creating endpoints in the codebase disagree with each other. *Disposition:* fix now (one annotation).

8. **`GlobalExceptionHandler.handleConstraintViolation` (`ConstraintViolationException`) appears currently unreachable** — it requires a `@Validated`-annotated bean with constrained method parameters, and neither `AuthController` nor `QuoteController` (the only two controllers) has one. No test exercises it. *Disposition:* accept as-is (forward-looking, documented) or remove — human call, not a defect either way; noting it so it isn't mistaken for covered.

9. **No test for `Authorization: Bearer ` (empty token)** — the one negative case that exercises a different underlying exception type (JJWT's `IllegalArgumentException`) than the other `JwtAuthenticationFilterTest` negative cases. *Disposition:* fix now (one test case, cheap).

10. **No fail-fast guard preventing the insecure default `jwt.secret` from reaching a non-dev environment.** Same category as an already-recorded Story 1.1 deferred item (Postgres dev credentials with "no separate profile that fails fast," `deferred-work.md`) — the project has no Spring profile infrastructure yet for either to hook into. *Disposition:* defer, bundle with the existing Postgres-credentials item once a real deployment target exists.

11. **Non-POST requests to `/api/v1/auth/register` or `/login` return `401 AUTH_UNAUTHENTICATED`** (falling through to `anyRequest().authenticated()`) **rather than `404`/`405`.** Cosmetic — a wrong-method request gets a misleading but still-safe rejection. *Disposition:* accept as-is; low value for the effort of per-verb-scoped matchers.

12. **No documented decision that staff roles (AGENT/LIQUIDATOR/ADMINISTRATOR) are locked out of the Quote module in Epic 1** — every quote endpoint hardcodes `hasRole('CLIENT')` with no staff path and no test per staff role (only `AGENT` is tested, as the generic "wrong role" case). Given Epic 2 is explicitly titled "Every Role Gets Their Own Workspace" and Epic 1's own spec never mentions staff quote access, this reads as intentional scope sequencing, not an oversight — but it isn't written down anywhere as such. *Disposition:* accept as-is; add a one-line note (README or `deferred-work.md`) so Epic 2's implementer doesn't have to rediscover this was deliberate.

### Reconciled during this retrospective (no action needed)

- **`CreateQuoteRequest.regionCode` has no `@Size` upper bound.** The edge-case-hunter lens flagged this as a gap; it is in fact the deliberate outcome of Story 1.5's own `bmad-code-review` (the `@Size(max=5)` constraint was removed specifically because it duplicated reference-data-shaped knowledge Bean Validation shouldn't encode — see `spec-1-5-quote-calculation-with-transparent-breakdown.md`'s Review Findings). An oversized string is cheaply rejected by the `region_zone_map` lookup miss regardless; no DoS or correctness concern. Recorded here so a future review doesn't re-flag it without this context.
- **BCrypt's 72-byte truncation vs. `@Size(max=100)` on password fields.** Re-surfaced by the edge-case-hunter lens; already tracked in `deferred-work.md` since Story 1.3's own review ("not urgent enough to block this story"). No new information — not re-added as a separate item.
- **Story 1.6's persisted/returned `regionCode` is the normalized form, not necessarily the literal client input.** Flagged by the aggregate-views analysis as a place "original" and "persisted" diverge; this is the explicitly documented outcome of Story 1.6's own review (`PricingResult.java`'s javadoc), not an oversight.
- **Rate limiting/lockout on `/login`.** Adversarial lens flagged this; Story 1.4's own spec (`spec-1-4-...md`, "Never" section) already names this an explicit non-goal for Milestone 1, sourced to a PRD decision (AD-3). Not a new finding.
