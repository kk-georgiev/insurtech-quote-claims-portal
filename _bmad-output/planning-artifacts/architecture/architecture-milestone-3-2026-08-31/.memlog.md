- (constraint) Inherited as binding read-only: M1 AD-1..AD-11 and M2 AD-1..AD-6. Not re-derived, not renumbered. M1 AD-6 authorizes creating the policy module now.
- (decision) AD-1 quote owns the acceptance transaction; policy depends on nothing. Alternatives weighed: (a) policy orchestrates and reads quote, (b) quote orchestrates and passes a fully-formed issuance command. Chose (b): acyclic, keeps BA 13.2's URL, and makes policy reusable unchanged when an AGENT issues on behalf in M5.
- (decision) AD-2 acceptance stays POST /api/v1/quotes/{id}/accept per BA 13.2 and returns the created policy, so one round trip both commits and renders. Policy reads live under /api/v1/policies in policy.api.
- (decision) AD-3 no status column on quotes or policies - status derived on read from accepted_at/valid_until and coverage dates. Prevents drift and removes the need for any scheduler. CANCELLED reserved in both enums with no producer and no persisted representation.
- (decision) AD-4 a policy copies every value it displays; policies.quote_id exists only as the idempotency key and is never dereferenced. No JPA association Policy->Quote. A policy row must be complete with the quotes table empty.
- (decision) AD-5 policies.quote_id UNIQUE is the sole idempotency authority; the application-level accepted_at check exists only for a friendly error on the uncontended path and must never be accepted as the guarantee. saveAndFlush inside try/catch, mapping DataIntegrityViolationException to QUOTE_ALREADY_ACCEPTED 409 - same pattern QuoteService.calculate already uses.
- (decision) AD-6 business zone Europe/Sofia, injected Clock, no production call to Instant.now/LocalDate.now. LocalDate+DATE for business dates, Instant+TIMESTAMPTZ for events. Boundaries inclusive at both ends; coverage_end = start.plusYears(1).minusDays(1). coverage_start is an acceptance input, not a quote input.
- (decision) AD-7 policy number from a global PostgreSQL sequence plus UNIQUE, format MI-{year}-{8 digits}. Sequence deliberately does not reset per year - the year is already in the string and a reset would need coordination. Gaps expected.
- (decision) AD-8 bonus-malus is tariff data in its own table owned by pricing. Order fixed: one_time = round((base + age_surcharge) x factor, 2), then + installment_fee - the factor never scales the flat fee. Unknown class fails closed, never defaults to neutral.
- (constraint) AD-8 provenance is binding, from the M3 PRD: the coefficients are the project's own demo model inherited from the prototype, not official or regulatorily determined Bulgarian market values. The disclaimer lives in the seed migration header, the README, the OpenAPI description and the UI - not only in the PRD.
- (decision) AD-9 every new column on an existing table is NOT NULL with its backfill in the same migration; only accepted_at is nullable because null carries domain meaning. Money backfills are arithmetically neutral (neutral class, factor 1.000) so persisted premiums stay byte-identical.
- (decision) AD-10 ownership enforced inside the query, never compared in Java afterwards. Someone else's resource returns 404, never 403 - 403 stays reserved for a role mismatch.
- (decision) AD-11 new codes QUOTE_EXPIRED 409, QUOTE_ALREADY_ACCEPTED 409, POLICY_NOT_FOUND 404, PRICING_UNKNOWN_BONUS_MALUS_CLASS 400, each shipping with bg+en in the same change; CI's error-code contract check is the gate.
- (decision) AD-12 list endpoints return a bare ordered JSON array of the same DTO the detail endpoint returns - no envelope, no pagination. Fixed so two list endpoints do not invent two shapes.
- (decision) AD-13 the quote response grows additively; no existing field is renamed or repurposed, so the M2 breakdown component keeps working untouched.
- (assumption) springdoc-openapi (FR-M3-14) is NOT version-verified against Spring Boot 4.1.1 - no web check was run in this lean pass. The spine instructs verification before binding and defers FR-M3-14 rather than pinning the framework backwards. It is a should-have precisely so it cannot hold the milestone.
- (event) spine finalized
- (decision) AD-5 revised 2026-08-31 per product owner correction: acceptance is genuinely idempotent, not just duplicate-protected. First success creates+returns the policy (201). Any later call for an already-accepted quote returns the SAME existing policy (200), read back via quote_id, never an error. Race: DataIntegrityViolationException on the unique constraint is caught and the loser re-reads and returns the winner's policy (200), not an error. No status column added.
- (decision) QUOTE_ALREADY_ACCEPTED (409) retired as a code - a 409 on replay would be duplicate-detection, not idempotency. 409 stays reserved for QUOTE_EXPIRED only. AD-11 updated to drop the code.
