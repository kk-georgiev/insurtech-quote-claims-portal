- (decision by user) Docker topology: single docker-compose.yml. 'docker compose up' = full stack (postgres+backend+frontend), 'docker compose up postgres' = DB only for local dev. Binds FR-12/FR-13. Prevents: divergent compose-file-per-environment sprawl.
- (decision by user) JWT: single access token, no refresh token mechanism for Milestone 1. Lifetime: a few hours (dev/demo-session-friendly). Binds FR-2. Prevents: refresh-token storage/rotation/revocation complexity that PRD Non-Goals already excludes.
- (decision by user) Module scaffolding: do NOT pre-create empty packages for customer/vehicle/policy/claim/notification/tariff. Created only when their first real feature lands. Prevents: empty-ceremony packages nobody owns yet.
- (decision by user) Non-Client placeholder screens (Agent/Liquidator/Admin) are purely static, role-labeled pages. No interactive elements. Binds FR-6.
- (version) Web-verified 2026-08-23: Spring Boot 4.1.1 (latest patch of team's chosen 4.x line), React Router v8 (current stable, June 2026, ESM-only), PostgreSQL 18 (current major, supersedes prototype's PG17), react-i18next (safest/most standard i18n choice, largest ecosystem).
- (decision) Module boundary rule: no module reaches into another module's persistence/domain package directly. All cross-module access goes through the target module's application-layer interface. Prevents: hidden coupling as policy/claim later need to call quote.
- (decision) API error envelope: {timestamp, status, code, message, fieldErrors}. code is the stable language-independent key frontend maps to a translation (binds FR-15); message is developer/log-only, never shown to end users directly. Adopted from team's earlier prototype pattern (GlobalExceptionHandler/ApiError), proven good.
- (decision) Frontend routing: React Router v8. Role guards (FR-7) are a single wrapper component around role-restricted routes, not scattered per-screen checks.
- (decision) Frontend i18n mechanism: react-i18next. Frontend data fetching: plain fetch + small typed API client module, no data-fetching library (React Query etc.) — too few screens to justify it this milestone.
