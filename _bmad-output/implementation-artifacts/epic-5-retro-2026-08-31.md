## Findings

Severity is consequence for the end user of the portal. Disposition: fix now / defer / accept.

### Aggregate view — spec-to-implementation reconciliation

**F1 — `@layer legacy` is now ~90% dead but was never progressively removed. (medium, defer)**
Source: `frontend/src/index.css:63-232`. After six stories, the legacy block still carries element-selector rules for `main`, `main > section`, `form div|label|input|select|textarea`, `button`, `button:hover|:focus-visible|:disabled`, and `dl`. Every screen that once consumed them now renders through `components/ui/` primitives whose `utilities`-layer classes override them. Stories 5.4 and 5.6 each removed *specific* dead rules (`header`, `[data-testid='language-toggle']`, `[role='alert']`, `[data-testid='register-success']`) but left the bulk. Only four legacy rules still have a live consumer: the `box-sizing` reset, `body` (colour/background/fallback font), `dt { font-weight: 600 }` (QuoteResult's `<dt>` has no weight utility), and `[data-testid='quote-result'] { padding-top; border-top }` (see F2). A reader opening this file today cannot tell live rules from dead ones — the block reads as load-bearing when it is mostly inert.

**F2 — FR-1's "no hardcoded hex on any touched screen" is violated via the legacy layer. (medium, defer)**
Source: `frontend/src/index.css:133-137` (`[data-testid='quote-result']`), `:226` (`dt { color: #475569 }` — overridden), `:110-111` (`main > section` — neutralised on the shells but the rule still ships). Epic 5's FR-1 has a testable consequence: *"No screen touched by this milestone contains a hardcoded hex color … every value resolves to a Tailwind token."* The stories satisfied this **in the JSX/className** but not in CSS: the quote-result `<section>` still renders a `border-top: 1px solid #e2e8f0` and `padding-top: 1.5rem` from the legacy rule (its `className="mt-6"` overrides only the `margin-top`), producing a hardcoded-hex divider line above the breakdown card on a live screen. The spec interpreted FR-1 as "no hex in the components/screens we author"; the as-built leaves hex in the stylesheet those screens pull in. Either reconcile FR-1's wording to that narrower reading, or finish the token migration (F1).

**F3 — `index.css:83-90` comment is now factually wrong. (low, fix now)**
Source: `frontend/src/index.css:83-90`. The comment (written by Story 5.4) says the retained legacy rules are *"still load-bearing for screens not yet migrated (e.g. `HealthStatus`)"*. Story 5.6 migrated `HealthStatus` to `<Card>`. No screen is unmigrated now. The comment actively misleads the next reader about why the block still exists.

### Aggregate view — duplication

**F4 — The submit-button loading pattern is triplicated verbatim. (low, defer)**
Source: `LoginForm.tsx:163-170`, `RegisterForm.tsx:153-160`, `QuoteForm.tsx:222-229`. Story 5.6 added the same block to all three forms:
```tsx
{submitting ? (<><Spinner className="mr-2" />{t('…submitting')}</>) : (t('…submit'))}
```
A `<Button loading>` prop (render the spinner, keep the label, force `disabled`) would have been one change point in the component the epic's own architecture names as the home for such behaviour (AD-2). Three copies means the next tweak to how a pending button looks is three edits, and a new form is expected to remember the incantation.

### Aggregate view — god-class / size growth

None. Highest net churn is `index.css` (+227 / −235, shrinking) and `FormField.tsx` (+74, a new file). The component library files are 37–74 lines each; no file grew past a healthy size. `git_evidence.py`: `binary_revisions: 0`, `merges_measured: 0` of `merge_count: 0` — the ranking is complete.

### Aggregate view — pattern divergence

**F5 — Speculative API surface with zero consumers after the whole epic. (low, accept / partial defer)**
Source: `Card.tsx:16` (`footer` prop — `grep` shows no screen passes it), `Button.tsx:16` (`variant="secondary"` — unused; only `primary` and `ghost` are consumed), `Spinner.tsx:13` (`size="md"` — unused; every caller takes the default `sm`). `Alert`'s unused `warning`/`info` variants are **not** in this list — AD-6 explicitly mandates the full four-value vocabulary regardless of consumers, so those are correct. For a *design-system* library, a `secondary` button and a `Card` footer slot are defensible forward-looking surface; `Spinner size="md"`, added in the time-boxed should-have story with no consumer and no near-term need, is the weakest. All three carry test weight on app-unexercised paths.

**F6 — `LanguageToggle` keeps a raw `<button>` with utility classes. (low, accept)**
Source: `LanguageToggle.tsx:52-58`. Documented and re-affirmed in both the 5.4 and 5.6 specs: a two-option segmented toggle is not one of the four base primitives, and the architecture scopes the library to Button/Input/FormField/Card. This is a recorded, intentional deviation — noted here so a future retro does not re-flag it.

### Aggregate view — architecture delta

Clean. New dependencies (`tailwindcss`, `@tailwindcss/vite`, `class-variance-authority`, `clsx`, `tailwind-merge`) all landed in 5.1 as the spine intended. New `frontend/src/components/ui/` layer; import direction is strictly screens → `ui/` → tokens, no cycles, no layering violation. `cn.ts` is the single shared merge helper and every primitive uses it.

**F9 — The "no behaviour change" discipline held perfectly. (win)**

Across six stories that rebuilt the markup of every screen, not one pre-existing behavioural test was modified or weakened. New coverage was *added* (182 → 220 tests, 6 new component test files). Every spec declared this constraint and every story met it. This is the single strongest signal in the epic.

**F10 — Review loops caught real defects before merge. (win)**
Source: spec Change Logs. 5.1's Tailwind-import strategy took two review-loop iterations to get right (the selective `theme.css`+`utilities.css` import, avoiding the preflight-vs-legacy reset collision). 5.2's `Card.titleAs` fix caught a silent `<h2>→<h3>` heading-level demotion that no test would have failed. 5.3 added an explicit `titleAs="h3"` to guard against a future default change. The per-story review layer was doing its job.

**F11 — Commit attribution was wrong for the first half of the epic. (low, accept — corrected mid-epic)**
