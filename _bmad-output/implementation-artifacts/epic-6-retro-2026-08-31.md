### Edge case / verification gap — fix now

`frontend/src/i18n/formatDate.ts` calls `new Intl.DateTimeFormat(language, {year, month, day}).format(new Date(isoDate))` with no `timeZone` option. A bare `LocalDate` string from the backend (e.g. `validUntil: "2026-12-31"`) parses as UTC midnight per the ECMAScript date-only-string rule (ECMA-262 §21.4.3.2), while `Intl.DateTimeFormat` without an explicit `timeZone` renders in the *viewer's local* zone. For any negative-UTC-offset viewer (the Americas), that shifts the displayed calendar date back by one day — `validUntil: "2026-12-31"` would read as "December 30" to someone in `America/Los_Angeles`. This did not surface in the live verification below because this session's browser and the backend both effectively sit at a non-negative offset, so the bug is real but was not directly observed here — it follows from documented `Date`/`Intl` semantics, not from a reproduction. Low current impact (target market is `Europe/Sofia`, a positive offset, where the same mechanism can push a date *forward* at worst on the rare instant right at a day boundary), but a genuine, sourced defect and a cheap fix: pass `timeZone: 'UTC'` so a calendar date renders identically regardless of viewer location. **Action item 3.**

### Ownership scoping — accept

Every new read path (`QuoteRepository.findAllByCustomerIdOrderByCreatedAtDesc`, reused `findByIdAndCustomerId`) keeps AD-10's rule: ownership lives in the query, a resource belonging to someone else is 404, and the frontend's `QuoteDetail` correctly renders that 404 as a "not found" state rather than a generic error — confirmed live (see below). No regression, no exception to the pattern.

### Reserved-value handling — accept

`QuoteStatus.CANCELLED` (backend enum), the frontend `QuoteStatus` type union, `quoteStatusPresentation.ts`, and `Badge`'s `neutral` variant all account for the reserved, not-yet-producible `CANCELLED` value consistently, without over-building anything a later story would have to unwind. Forward-compatible, appropriately minimal.
