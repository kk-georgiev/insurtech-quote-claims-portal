- **Compatibility gate honored, not assumed** — springdoc-openapi 3.1.0's compatibility with Spring Boot 4.1.1 was verified directly against the GitHub releases page before adding the dependency (`backend/pom.xml:87-98`), matching the story's own explicit go/no-go AC.

- **No behavior change to existing endpoints** — verified live (login/register still public, quotes still 401 without a token) and by the full 161-test backend suite passing.
- **Review-loop catch, already fixed before merge:** the initial permit-list (`SecurityConfig.java`) covered `/swagger-ui/**` but not springdoc's conventional `/swagger-ui.html` entry point, which two independent review layers (blind-hunter, edge-case-hunter) caught converging on the same finding. **Story 9.2 (Documentation and Legacy-CSS Cleanup):**

No spec-to-implementation divergence found in either story.

### Process finding — the Epic 8 sprint-status-lag fix did not hold on its very next test

**This is the epic's most significant finding.** Epic 8's retro (action item 1) escalated a sprint-status lag recurring across three consecutive epics (5, 6, 8) and landed a fix in PR #67: `CONTRIBUTING.md` §3 and the PR template now require a story's status to move to `done` in the *same PR* that closes it — merged into `dev` immediately before Story 9.1's own PR.

Checked directly against both commits that followed it:
- **`git show 262559a -- sprint-status.yaml`** (PR #68, Story 9.1's own merge commit): sets `9-1-openapi-documentation-should-have` to `review`, not `done`. The very first PR to merge after the fix landed did not follow it.
- **`git show f00a2aa -- sprint-status.yaml`** (PR #69, Story 9.2's own merge commit): sets `9-1` to `done` (as a side effect of this retro's own merge-conflict resolution, not because PR #69's author set it) and leaves `9-2-documentation-and-legacy-css-cleanup-should-have` at `review` — its own story, still not `done` in its own closing PR.

Both of the two PRs immediately following the process fix missed it. This isn't a new instance of the original lag (nothing was left stale for epics — this retro caught both within the same session) — it's direct, immediate evidence that a documentation-only fix (a checklist line in `CONTRIBUTING.md` + the PR template) is not sufficient to change the actual behavior, even in the very next PR. See Action items.
